## Источники трафика и запись сессий

Панель показывает источники и каналы, кампании, страницы входа (без маркетинговых query-параметров), посетителей,
долю BOT, отдельно известных краулеров, заявки и качественные заявки. Период,
источник, канал и фильтр «С записью» применяются к сессиям, CSV и отчёту.
Нажатие строки отчёта открывает сессии этой кампании и страницы входа.
Качество классификации и каталог ботов показывают данные проекта за всё время.

При открытии отчёта строки для графика отмечены по умолчанию, максимум 20
с наибольшим числом визитов. Галочки можно снять вручную, в том числе все;
тогда график показывает только общий итог.

Первоначальный referrer и UTM фиксируются для сессии; внутренние переходы их
не заменяют. Рекламные click ID не переносятся из истёкшей сессии в новую.
Без внешнего referrer и меток показывается «Прямой / неизвестный», поскольку
браузер или приложение могут скрыть источник. Старые визиты имеют
`attribution_basis=historical_*`: восстановить ранее перезаписанный referrer
невозможно. Просмотры страниц сохраняются отдельно от сырых событий.
Tracker автоматически отмечает `pushState`, `replaceState`, `popstate`;
ручное событие `clickshield:pageview` поддерживается, повтор одного URL
не создаёт ещё один просмотр.

Запись включается в **Проекты → Запись сессий**: доля 0–100%, хранение 1–30 дней
(по умолчанию 7). По умолчанию в новом проекте запись выключена. Доля выбирается
один раз для сессии. При сокращении срока хранения старые записи тоже получают
более ранний срок удаления. Отключение записи останавливает приём новых блоков;
ранее сохранённые записи доступны до истечения срока или ручного удаления.

Используется rrweb 2.1.7 (MIT). Запись — DOM-снимки и события, а не видеофайл.
В карточке сессии доступны выбор страницы, воспроизведение/пауза, перемотка,
скорости 1×/2×/4×/8× и удаление записи. Содержимое воспроизводится внутри
sandbox iframe без разрешения выполнения скриптов. Неполные блоки не выдаются
как полноценная запись: плеер предупреждает о пропусках и требует полный снимок.
Периодический полный снимок создаётся раз в минуту.

Значения всех полей маскируются на клиенте до отправки. `data-cs-private`,
`data-private`, `.cs-private`, `.rr-block` полностью скрывают блок;
`data-cs-mask`, `.rr-mask`, `.personal-data` скрывают текст. Дополнительно
удаляются обработчики событий, адреса отправки форм, URL credentials и
неразрешённые query-параметры, маскируются распознаваемые email и номера
в тексте. Это не универсальное распознавание персональных данных: чувствительные
области личного кабинета и результаты заполненных форм надо явно исключить.
Сторонние iframe, canvas, видео и сетевые/console-логи не записываются.
Картинки и стили зависят от доступности исходных ресурсов и CSP; защищённые
ресурсы и URL с подписанными параметрами могут не воспроизводиться.
Если сайт запускает tracker после согласия, запись стартует вместе с ним.

Блоки хранятся gzip в закрытом S3 bucket; PostgreSQL хранит их метаданные.
Повторная отправка
того же фрагмента идемпотентна; конфликт содержимого отклоняется. Один фрагмент
ограничен 128 КиБ, группа — 64 фрагментами, запись — 20 МиБ исходных данных,
клиентская очередь — 8 МиБ, непрерывная запись страницы — одним часом.
Ограничение API — 32 МиБ/мин на проект и адрес; чтение и удаление требуют входа.
Финальный beacon ограничен общим бюджетом браузера: резкое закрытие страницы
или потеря сети может оставить неполную запись. Политика хранения распространяется
на рабочую БД; архивы резервных копий удаляются по отдельному сроку.

### Чтение отчётов Метрики

В **Проекты → Чтение отчётов Яндекс Метрики** задаются номер счётчика и отдельный
OAuth-токен с правом `metrika:read`. Токен шифруется AES-GCM и никогда не возвращается
в браузер. Measurement Protocol token для отправки целей для чтения не подходит.
Пустое поле OAuth-токена сохраняет ранее введённый токен; кнопка удаления удаляет
подключение. [Получение OAuth-токена](https://yandex.ru/dev/metrika/ru/intro/authorization).

В панели выберите один проект, период и отчёт: источники, кампании Директа,
площадки Директа или UTM, затем «Загрузить из Метрики». API использует последний
источник (`last`), запрашивает полную точность и показывает информацию о
семплировании, если Метрика его применила. По 500 строк на страницу, период до
366 дней. Даты отчёта интерпретируются в часовом поясе счётчика. Собственная
аналитика интерпретирует выбранные даты в часовом поясе браузера.

Отчёты Метрики показаны отдельно: её посетители, визиты, атрибуция и правила
определения ботов могут отличаться от ClickShield. Записи нашего плеера не
импортируются из Яндекс Вебвизора; собственный recorder нужен для новых визитов.
Текущая интеграция не выполняет неоднозначное сопоставление визитов по ClientID.

### Проверка и обновление библиотек

Vendored JS/CSS встроены в Go-бинарник, runtime CDN не требуется. Для воспроизводимого
обновления: измените версии в `package.json`, выполните `npm install --ignore-scripts`
и `npm run vendor`, затем проверьте реальные запись и воспроизведение. MIT notice
лежит рядом с JS в `internal/httpapi/assets/rrweb-LICENSE.txt`.

Интеграционные проверки с отдельной PostgreSQL:

```bash
CLICKSHIELD_TEST_DATABASE_URL=postgres://... go test -race ./...
go vet ./...
node --check internal/httpapi/assets/tracker.js
node --check internal/httpapi/assets/admin.js
node --check internal/httpapi/assets/replay-recorder.js
node --check internal/httpapi/assets/replay-viewer.js
```

Проверяются сохранение источника, история страниц, разбиение записи,
повторы без расходования квоты, конфликты, неполная запись, запрет чужого проекта,
отключение записи и TTL; HTTP-проверки защищают валидацию и очищенные URL;
Reporting API проверяется локальным HTTP-сервером без рабочих OAuth-токенов.

### Отдельная страница аналитики

В меню «Аналитика» (`/analytics`) доступны отчёты по источникам, referrer,
кампаниям, UTM, поисковым фразам, страницам входа и выхода, устройствам, браузерам,
географии, языкам, сетям, качеству, ботам, дням, часам и активности. Фильтры: проект, период, канал и классификация; быстрые периоды — сегодня,
7 и 30 дней. CSV выгружает все строки выбранного отчёта. Нажатие строки открывает
сессии с соответствующими фильтрами и доступом к записям посещений.

Итоги считают уникальных посетителей по всему периоду отдельно от строк отчёта.
Конверсия — доля визитов с хотя бы одной заявкой: несколько заявок в одном визите
не увеличивают конверсию выше 100%. Просмотры берутся из истории страниц или
исторических признаков (минимум один на визит). Среднее время — рассчитанная
длительность, а до расчёта — интервал от первого до последнего события; это не
показатель активного времени. Дневной отчёт использует часовой пояс браузера.

Отчёты самого счётчика Яндекс Метрики перенесены на эту же страницу в отдельный
раскрываемый блок. Для них по-прежнему нужен OAuth-доступ с `metrika:read`;
итоги ClickShield собираются собственным трекером и не требуют OAuth.
API агрегированных отчётов: `GET /v1/reports?report=sources&timezone=Europe/Moscow`.

## Хранение после архитектурного обновления

Replay хранится в закрытом S3-совместимом bucket, PostgreSQL содержит ключи,
checksum и размеры фрагментов. `REPLAY_S3_*` задаются на сервере; включение replay
без хранилища возвращает 503. Удаление сразу убирает запись из API и запрещает
повторный upload этой сессии. Worker удаляет объекты через устойчивую очередь
после защитной задержки 5 минут; ошибки повторяются через минуту.

Upload сначала резервирует квоту в БД, затем пишет неизменяемый объект и отмечает
фрагмент готовым. Повтор не увеличивает квоту; сбой оставляет PENDING, который
можно дозагрузить тем же запросом. Неполные записи обозначаются в API/плеере.
Старые `bytea` переносит `clickshield backfill replay` до запуска новой версии.

## Границы визита в трекере

После 30 минут без взаимодействий трекер прекращает heartbeat и запись DOM.
Следующее действие создаёт новый `session_id`, первую страницу и отдельную
запись replay без перезагрузки сайта. `ClickShield.sessionId` возвращает текущий
ID: считывайте его непосредственно перед отправкой заявки. Пакеты повторяются
с исходными ID и данными визита, даже если за время сетевого сбоя начался новый визит.
Фоновый heartbeat без активности не продлевает серверный `last_seen_at`.
