# Продуктовая аналитика ClickShield

Раздел `/analytics` содержит отчёты аудитории и блок «Поведение и цели». Миграции применяет отдельная команда `clickshield migrate`. Отчёты читают
проекции в схеме `analytics`, обновляемые отдельным worker через outbox.
При остановленном worker данные в отчётах остаются на последнем доставленном
состоянии; очередь и её задержка доступны в `/v1/operations`. Обновите Go-бинарник и tracker.js на сайте: старые трекеры не отправляют бизнес-события и размеры документа для новых карт.

## Бизнес-события

После загрузки трекера:

```js
window.ClickShield.track('phone_call', {placement: 'header', mobile: true});
window.ClickShield.track('signup', {plan: 'pro', variant: 'B'});
```

Или без своего обработчика:

```html
<button data-cs-event="phone_call" data-cs-prop-placement="header">Позвонить</button>
```

Имена: 1–80 символов. Параметры: до 32 ключей, строки до 1024 байт, числа, boolean и null; вложенные объекты запрещены; общий объём до 8 KiB. HTML-атрибуты передают строки. События используют пакетную очередь трекера и её повторы. Не передавайте контактные данные и содержимое форм в параметры. Маскирование DOM-записей не маскирует явно заданные бизнес-параметры.

В отчёте «Бизнес-события» показаны срабатывания, визиты и посетители. Нажмите событие, чтобы увидеть параметры (до 500 сочетаний ключ/значение). Эти данные хранятся до удаления сессий по AGGREGATE_TTL, независимо от RAW_EVENTS_TTL.

## Цели и воронки

Выберите один проект и нажмите «Создать цель или воронку». Цель содержит один шаг, воронка — 2–12. Типы шагов:

- `page`: полный адрес без query или путь `/contacts`; точное совпадение или префикс;
- `event`: имя бизнес-события; можно фильтровать параметры по JSON с сохранением типов;
- `outcome`: `LEAD` (любая заявка), `SUBMITTED`, `QUALIFIED`, `SPAM`, `LOST`.

Воронки проходят в одном визите, в заданном порядке, с окном 1–10080 минут между соседними шагами. Посторонние действия разрешены. Одно событие не закрывает два одинаковых шага. Повторный старт учитывается даже после истечения предыдущей попытки. Числа — уникальные визиты, не количество срабатываний. Можно изменить и удалить определения; отчёт пересчитывается по сохранённой истории.

Даты и сегменты отчётов выбирают сессии по началу визита; анализ включает действия в этих сессиях. Отправка заявки доступна как SUBMITTED/LEAD даже после обновления результата; остальные статусы отражают текущее состояние. Для QUALIFIED/SPAM/LOST используется время последнего обновления результата. История всех промежуточных смен статуса заявки не сохраняется.

## Маршруты, карты и удержание

«Пути посетителей» объединяет переходы страниц, входы `[entry]` и последние страницы `[exit]`; показывает до 200 наиболее частых рёбер, число переходов и уникальных визитов. Последняя страница не доказывает закрытие сайта: активный визит может продолжаться.

Карты кликов и прокрутки разделены по URL без query и точной ширине окна. Кликовые координаты нормализованы по ширине окна и высоте документа; это агрегированная сетка, а не снимок страницы. Прокрутка показывает число визитов, достигших глубины, включая начальную видимую область. Сохраняются только клики/прокрутки, не движения мыши. Карты живут до удаления сессий; фильтр классификации позволяет смотреть людей отдельно от ботов.

Удержание: ежедневные когорты первого визита и возвраты Д0–Д30, с часовым поясом выбранного отчёта. Фильтры выбирают состав когорты по первому визиту; возвраты учитываются во всех её сессиях и могут выходить за период отбора. Будущие дни не изображаются как нулевое удержание. Первый визит определяется по сохранённой истории; очистка старых сессий меняет доступный горизонт. Visitor ID относится к браузеру, а не гарантированно к человеку на нескольких устройствах.

## Аудитория и GeoIP

Доступны отчёты страны → регионы → города, устройства/ОС, браузеры и языки. Язык — настройка браузера, не национальность. UA-разбор использует фиксированные семейства; неизвестные клиенты остаются неизвестными.

Docker-образ уже содержит GeoLite2 City в `/app/GeoLite2-City.mmdb`, а Compose
задаёт `GEOIP_CITY_DATABASE` с этим путём по умолчанию. База загружается при
сборке образа. Для прямого запуска бинарника или своей GeoIP2/GeoLite2 City
(либо совместимой MMDB) задайте путь к локальному файлу:

```dotenv
GEOIP_CITY_DATABASE=/app/geoip/GeoLite2-City.mmdb
```

При использовании своего файла в Docker смонтируйте каталог базы read-only
в `/app/geoip` через Compose override для app и worker. Для обновления встроенной
базы пересоберите образ без кэша загрузки, как описано в
[руководстве эксплуатации](operations.md). Заданный неверный путь вызывает
ошибку старта. HTTP-запросы к внешнему GeoIP-сервису не отправляются.
При TRUST_PROXY_HEADERS=true можно получать CF-IPCountry, X-GeoIP-Region и
X-GeoIP-City; прокси обязан заменять/очищать клиентские значения. Если источника
нет, значения остаются пустыми. Страна регистрации ASN не подменяет географию
посетителя.

## Ссылки, пиксели и отметки

В панели «Ссылки, пиксели, отметки» выберите один проект. Короткие ссылки `/l/{slug}` перенаправляют на настроенный HTTP(S)-адрес, сохраняя явно указанные UTM. Название, назначение и короткий адрес редактируются; ссылки можно отключать или удалять. HEAD-проверки не учитываются.

Пиксель `/p/{uuid}` возвращает прозрачный GIF 1×1 с запретом кэширования. В панели выдаётся HTML-сниппет. Можно отключать и удалять пиксели. Статистика ссылок и пикселей — запросы, включая сканеры почтовых сервисов; это не уникальные пользователи и не доказательство прочтения письма. Попадания хранятся по AGGREGATE_TTL. IP-адреса в этой статистике не записываются.

Отметки задаются датой/временем и текстом, выводятся на временном графике выбранного проекта. Можно отмечать запуск кампании или изменение страницы и редактировать/удалять записи. Список отметок фильтруется периодом.

## API, SDK и MCP

Отчёты, цели и инструменты доступны по API-токену с правом `analytics:read`
(изменения — `analytics:write`). Токены выпускаются в разделе «API и MCP»;
права и маршруты описаны в [HTTP API](api.md#api-токены), подключение ИИ-агентов —
в [MCP](mcp.md). JS/TypeScript SDK: `sdk/index.js`, `sdk/index.d.ts`, примеры в
`sdk/README.md`. Используйте его на сервере, не включайте токен в frontend.

## Проверка

```bash
CLICKSHIELD_TEST_DATABASE_URL=postgres://... go test -race ./...
go vet ./...
node --test sdk/index.test.mjs scripts/replay-privacy.test.mjs
node --check internal/httpapi/assets/product-analytics.js
node --check internal/httpapi/assets/analytics-tools.js
```

Тестовая БД должна быть отдельной от рабочей. Проверки покрывают идемпотентность, сохранение событий после очистки raw, воронки с повторными стартами, типы параметров, часовой пояс когорт, карты, GeoIP, изоляцию проектов, отзыв ключей, настоящий MCP-клиент, redirect и GIF.
